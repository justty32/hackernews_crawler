1.  **與現有及歷史解決方案的比較：**
    *   **CoLinux 與 flinux：** 許多留言者將此專案與早期的 CoLinux 和 flinux 進行比較。CoLinux 被認為是像 WSL2 的前身，透過側載 Linux 核心來運行，在 Windows XP 時代非常受歡迎，特別是用於建立開發環境（如 LAMP 堆疊），被譽為一項「技術壯舉」。flinux 則被比作 WSL1 的架構。
    *   **Cygwin 與 MSYS2：** Cygwin 歷史更悠久（1995 年），旨在提供 Windows 上的原生 POSIX 二進制支援，最初被認為是輕量級且「正確」的方法。然而，許多留言者指出其缺點，包括「DLL 地獄」、運行緩慢、兼容性不佳、需要重新編譯，以及其內部實現的「巫術」性質，導致在現代 Windows 環境（如 AppContainer）中無法運行。MSYS2 作為 Cygwin 的現代繼承者，它利用了 Arch Linux 的 pacman 套件管理器，提供了一個更友善的在 Windows 上運行原生 POSIX 二進制檔案的解決方案。

2.  **專案的技術難度與驚人程度：**
    *   許多人對這個專案的技術難度表示驚嘆，稱其為「不可能的壯舉」或「魔法」，並對作者理解 Windows 9x 內部運作的深厚知識感到印象深刻。
    *   有留言解釋說，Windows 9x 之前的作業系統並未充分利用處理器提供的記憶體保護和多工處理硬體功能。這個專案正是利用了這一點，讓 Linux 核心能夠「接管」這些硬體資源，從而在 Windows 9x 中運行。儘管技術上令人驚嘆，但其實際應用場景（尤其是在 486 時代的記憶體限制下）主要被視為「駭客價值」。
